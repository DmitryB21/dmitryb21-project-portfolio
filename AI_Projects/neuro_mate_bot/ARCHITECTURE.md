## Принципы архитектуры

### 1. Модульность
- Каждый модуль отвечает за свою область ответственности
- Минимальная связанность между модулями
- Максимальное сцепление внутри модуля

### 2. Разделение ответственности
- **handlers/** - обработка пользовательских взаимодействий
- **services/** - бизнес-логика, работа с данными
- **models/** - структуры данных
- **keyboards/** - создание клавиатур
- **states/** - FSM состояния

### 3. Test-First подход
- Каждый функционал описан тестовыми сценариями (Given/When/Then)
- Тесты описаны в `tests/scenarios.md` перед реализацией

### 4. Изоляция модулей
- Каждый модуль может быть протестирован отдельно
- Зависимости через интерфейсы/функции, а не прямые импорты классов

## Описание модулей

### bot/main.py
- Инициализация бота и диспетчера
- Регистрация роутеров (порядок важен!)
- Запуск polling

### bot/handlers/start.py
- Обработка команды `/start`
- Показ приветственного сообщения
- Показ главной Reply-клавиатуры
- Сброс FSM состояния при необходимости

### bot/handlers/tasks.py
- Обработка кнопки "Добавить задачу"
- FSM для добавления задачи (название → время → сохранение)
- Обработка кнопки "Просмотреть задачи"
- Показ списка задач с Inline-кнопками
- Обработка callback для изменения статуса на "Выполнена"
- Обработка callback для удаления задачи
- Уведомление после выполнения 2 задач

### bot/handlers/deals.py
- Обработка кнопки "Добавить сделку"
- FSM для добавления сделки (название → сумма → статус → сохранение)
- Обработка кнопки "Просмотреть сделки"
- Показ списка сделок с Inline-кнопками
- FSM для изменения статуса сделки
- Обработка callback для изменения статуса сделки

### bot/handlers/report.py
- Обработка команды `/report`
- Показ статистики по закрытым сделкам за текущую сессию
- Отображение количества закрытых сделок и общей суммы

### bot/handlers/extras.py
- Обработка кнопки "Получить совет по маркетингу"
- FSM для запроса описания проблемы
- Интеграция с ChatGPT API для получения совета
- Обработка кнопки "Получить мотивацию"
- Интеграция с ChatGPT API для генерации мотивационных фраз

### bot/handlers/errors.py
- Обработка команды `/help`
- Обработка неизвестных команд
- Обработка неизвестных сообщений (fallback)

### bot/states/task_states.py
- `TaskAddStates` - группа состояний для добавления задачи:
  - `waiting_for_title` - ожидание названия задачи
  - `waiting_for_time` - ожидание времени задачи (формат HH:MM)

### bot/states/deal_states.py
- `DealAddStates` - группа состояний для добавления сделки:
  - `waiting_for_title` - ожидание названия сделки
  - `waiting_for_amount` - ожидание суммы сделки
  - `waiting_for_status` - ожидание выбора статуса сделки
- `DealChangeStatusStates` - группа состояний для изменения статуса сделки:
  - `waiting_for_status` - ожидание выбора нового статуса

### bot/states/marketing_states.py
- `MarketingAdviceStates` - группа состояний для получения совета:
  - `waiting_for_problem` - ожидание описания проблемы

### bot/keyboards/reply.py
- `get_main_keyboard()` - главная Reply-клавиатура с кнопками:
  - "Добавить задачу"
  - "Добавить сделку"
  - "Просмотреть задачи"
  - "Просмотреть сделки"
  - "Получить совет по маркетингу"
  - "Получить мотивацию"

### bot/keyboards/inline.py
- `get_task_keyboard(task_id, status)` - Inline-клавиатура для задачи
- `get_tasks_list_keyboard(tasks)` - Inline-клавиатуры для списка задач

### bot/keyboards/deal_inline.py
- `get_deal_keyboard(deal_id)` - Inline-клавиатура для сделки с кнопкой "Изменить статус сделки"
- `get_deals_list_keyboard(deals)` - Inline-клавиатуры для списка сделок

### bot/services/task_service.py
- `create_task(user_id, title, time_str)` - создание задачи (формат времени HH:MM)
- `get_user_tasks(user_id)` - получение задач пользователя
- `update_task_status(task_id, status)` - обновление статуса задачи
- `delete_task(task_id)` - удаление задачи
- `get_task_by_id(task_id)` - получение задачи по ID
- `get_task_statistics(user_id)` - получение статистики по задачам

### bot/services/deal_service.py
- `create_deal(user_id, title, amount_str, status)` - создание сделки
- `get_user_deals(user_id)` - получение сделок пользователя
- `get_deal_by_id(deal_id)` - получение сделки по ID
- `update_deal_status(deal_id, status)` - обновление статуса сделки
- `delete_deal(deal_id)` - удаление сделки
- `get_closed_deals_statistics(user_id)` - получение статистики по закрытым сделкам

### bot/services/chatgpt_service.py
- `get_marketing_advice(problem_description)` - получение совета по маркетингу от ChatGPT
- `get_motivation()` - получение мотивационной фразы от ChatGPT
- Интеграция с OpenAI API (gpt-3.5-turbo)

### bot/services/storage.py
- `InMemoryStorage` - in-memory хранилище для задач и сделок
- Методы для работы с задачами (CRUD)
- Методы для работы со сделками (CRUD)
- Методы для получения статистики

### bot/models/task.py
- `Task` - класс модели задачи:
  - `id` - уникальный идентификатор
  - `user_id` - ID пользователя Telegram
  - `title` - название задачи
  - `time` - время выполнения (datetime)
  - `status` - статус ("Не выполнена" / "Выполнена")
  - `created_at` - дата создания

### bot/models/deal.py
- `Deal` - класс модели сделки:
  - `id` - уникальный идентификатор
  - `user_id` - ID пользователя Telegram
  - `title` - название сделки
  - `amount` - сумма сделки (float)
  - `status` - статус ("Открыта" / "В процессе" / "Закрыта")
  - `created_at` - дата создания
  - `closed_at` - дата закрытия (опционально)

## Потоки данных

### Добавление задачи:
1. Пользователь → `/start` → `handlers/start.py`
2. Пользователь → "Добавить задачу" → `handlers/tasks.py` → FSM `waiting_for_title`
3. Пользователь → название → `handlers/tasks.py` → FSM `waiting_for_time`
4. Пользователь → время (HH:MM) → `handlers/tasks.py` → `task_service.create_task()` → сохранение

### Просмотр задач:
1. Пользователь → "Просмотреть задачи" → `handlers/tasks.py`
2. `task_service.get_user_tasks()` → получение задач
3. Формирование сообщения → `keyboards/inline.py` → показ списка с кнопками

### Изменение статуса задачи:
1. Пользователь → Inline-кнопка "✅ Выполнена" → `handlers/tasks.py` (callback)
2. `task_service.update_task_status()` → обновление
3. Проверка количества выполненных задач → уведомление при достижении 2 задач
4. Обновление сообщения → показ нового состояния

### Добавление сделки:
1. Пользователь → "Добавить сделку" → `handlers/deals.py` → FSM `waiting_for_title`
2. Пользователь → название → `handlers/deals.py` → FSM `waiting_for_amount`
3. Пользователь → сумма → `handlers/deals.py` → FSM `waiting_for_status`
4. Пользователь → выбор статуса (Inline-кнопка) → `handlers/deals.py` → `deal_service.create_deal()` → сохранение

### Просмотр сделок:
1. Пользователь → "Просмотреть сделки" → `handlers/deals.py`
2. `deal_service.get_user_deals()` → получение сделок
3. Формирование сообщения → `keyboards/deal_inline.py` → показ списка с кнопками

### Изменение статуса сделки:
1. Пользователь → Inline-кнопка "Изменить статус сделки" → `handlers/deals.py` → FSM `waiting_for_status`
2. Пользователь → выбор нового статуса (Inline-кнопка) → `handlers/deals.py` → `deal_service.update_deal_status()` → обновление
3. Обновление сообщения → показ нового состояния

### Получение совета по маркетингу:
1. Пользователь → "Получить совет по маркетингу" → `handlers/extras.py` → FSM `waiting_for_problem`
2. Пользователь → описание проблемы → `handlers/extras.py` → `chatgpt_service.get_marketing_advice()` → запрос к OpenAI API
3. Получение ответа → отправка совета пользователю

### Получение мотивации:
1. Пользователь → "Получить мотивацию" → `handlers/extras.py`
2. `chatgpt_service.get_motivation()` → запрос к OpenAI API
3. Получение ответа → отправка мотивационной фразы пользователю

### Команда /report:
1. Пользователь → `/report` → `handlers/report.py`
2. `deal_service.get_closed_deals_statistics()` → получение статистики
3. Формирование отчета → отправка пользователю

## Хранилище данных

**Текущий этап:** In-memory хранилище (словарь Python)
- Простота для первого этапа
- Данные теряются при перезапуске
- Хранит задачи и сделки в памяти

**Будущие этапы:** 
- SQLite для локальной разработки
- PostgreSQL для production

## Интеграции

### OpenAI ChatGPT API
- Используется для генерации советов по маркетингу
- Используется для генерации мотивационных фраз
- Модель: gpt-3.5-turbo
- Требуется API ключ в переменных окружения (`OPENAI_API_KEY`)

## Безопасность

- Валидация всех пользовательских данных
- Проверка прав доступа к задачам и сделкам (только владелец может изменять/удалять)
- Санитизация входных данных
- Безопасное хранение API ключей в переменных окружения
